04 / PRODUCT OPPORTUNITY

Meeting-to-Slides
应该是一条工作流。

不是“把 Transcript 丢进模型”那么简单。逐步点击下面五个阶段，查看 Zoom 可以真正创造差异化的环节。

01 / CAPTURE

识别真正的会议上下文

不是所有会议都需要一份 Slides。先判断会议类型、参与者角色、确定的决策与尚未达成共识的事项，并保留可追溯来源。

05 / STRATEGIC ACTIONS

What Zoom Slides
should do next.

按真实用户价值、实现依赖与证据充分度排优先级，不代表团队已批准 Roadmap。

HIGHEST PRIORITY / THIS CYCLE

Now.

  1. 与 UCL / Onyx 团队明确 Slides 可调用的数据能力、权限继承和可用时间表
  2. 拿真实会议 + 企业 Docs 做带来源引用的 Slides 试验
  3. 增加生成前大纲审核，比较 Time-to-Deliver 与事实错误率
MEASURE → VERIFIED CLAIMS / TIME TO DELIVER
BUILD THE ADVANTAGE

Next.

  1. 建立 Meeting → Research → Outline → Editable Slides 的渐进式 AI 创建流程
  2. 让 Suite Agent 安全读写 Slides，支持明确的审批、回滚与来源追溯
  3. 验证企业知识、品牌规范与会议上下文的组合效果
VALIDATE → REUSE / AUDITABILITY / BRAND FIT
NEEDS FURTHER EVIDENCE

Watch.

  1. Onyx 是否形成可控的数据治理与 Slide 引用能力，而非仅完成收购
  2. Google Notebook 的 Slide Deck 是否支持原生元素深度编辑
  3. Canva Craft 的设计分层生成是否真正降低用户修稿时间
NO COMMITMENT WITHOUT TESTING
关键风险 /Zoom 上下文能力的公开发布，不意味着所有组件已在 Zoom Slides 可用。不能把计划中的 enriched notes、个性化代理能力或 Onyx 集成写成当前已交付功能；对于未确认的会议决定，应标注证据与不确定性。
